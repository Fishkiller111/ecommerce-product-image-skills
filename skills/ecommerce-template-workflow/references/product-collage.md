# 商品拼图：将两张照片里的商品主体合到一张图

## 适用与输入

当用户说“拼图”，取本次提供的两张真实商品原图，**分别抠出商品主体再组合**，不要把带背景的整张照片简单上下拼接，也不要把其中一张当成风格图或以 AI 重画商品。图一、图二按用户的附件顺序或明确指认确定，不能按文件名排序。缺少其中一张原图时说明缺失，不用其他照片或占位图冒充。

优先遵循用户的位置关系：

| 用户说法 | `--layout` | `--order` |
| --- | --- | --- |
| 图一在上，图二在下 | `vertical` | `1-2` |
| 图二在上，图一在下 | `vertical` | `2-1` |
| 图一在左，图二在右 | `horizontal` | `1-2` |
| 图二在左，图一在右 | `horizontal` | `2-1` |

没说方向时默认图一在后、图二在前，并在交付时说明。**两件商品必须自然地放在同一个连续支撑平面上，不得无支撑悬空。**当用户说“图一在上、图二在下”时，默认用同一地面上的前后景错位表达：图一的接触位置靠画面上方（远处），图二靠下方（近处），横向适当错开避免遮挡；不用将两个像素框无支撑地完全上下分离。左右排列时两件商品使用共同地面基线。用户明确要求叠放时，须确认下方物体确实能提供稳定支撑；不能机械地把箱子堆在软管上冒充合理摆放。

在可见接触部位增加自然的接触阴影，远近、光向、光色、阴影方向及底面的透视保持一致。脚本仅根据 2D 轮廓做视觉近似，不是物理仿真或三维重建，无法自动保证所有物体的真实光照、材质、支撑、比例和透视；最终必须打开成图人工检查。有不可信的悬浮、阴影脱离、错误视角或漂浮叠放时，不得当合格成图交付；需要时改构图、使用同角度合照、取得尺寸信息或另行人工调整，不得凭空重绘包装。

主体默认等比且不旋转，只增加中性的地面背景与阴影，不添加文字、价格、装饰物或商品数量。`--gap 0` 可让两件商品的横向边界贴近。脚本不支持自由重叠或斜放；用户明确要求这类构图时需另用可控的本地合成方式，核对支撑与遮挡。

两张不同照片的拍摄距离可能不同。默认按各自的**原始主体像素**以相同倍率合成，并不代表真实实物比例；只有用户明确提供或要求相对比例时才分别调整。用户明确要求旋转时可用脚本中的 90° 倍数选项；不要自行旋转，让包装字变形或重写。合成结果可供后续做主图、详情图，但不能因此丢失每张原照的来源、蒙版和清晰度记录。

## 本机执行

在 Agent 内找到本技能目录 `WORKFLOW_DIR` 和同级 `psb-template-product-swap`，按后者说明配置 Python/依赖。抠图和合成默认都在本机执行，不调用 APIMart 或上传原照；macOS 原照使用系统 Vision，Windows 使用本地 CPU 模型，首次下载模型需联网。已带透明通道的真实 PNG 直接使用；不把白底照片当透明图，白色软管、盖子、包装边缘尤其要复核。

macOS（`PSB_PYTHON` 可指向已装依赖的解释器）：

```bash
COLLAGE_PYTHON="${PSB_PYTHON:-python3}"
"$COLLAGE_PYTHON" "$WORKFLOW_DIR/scripts/render_collage.py" "$IMAGE_1" "$IMAGE_2" \
  --layout vertical --order 1-2 --out "$OUT_ROOT"
```

Windows PowerShell（先按同级技能说明配置 `$env:PSB_PYTHON`）：

```powershell
& $env:PSB_PYTHON (Join-Path $WorkflowDir 'scripts\render_collage.py') $Image1 $Image2 `
  --layout vertical --order 1-2 --out $OutRoot
```

`OUT_ROOT` 默认项目的 `outputs/product-collage`；自动创建唯一编号和独立目录，已有结果不覆盖，不需要用户提供编号或写 JSON。常用可选参数：

- `--size 1080x1440`：指定画布；不指定时根据两个原始主体和共同地面布局自动确定。画布宽高限 64–4000 像素且总量不超过 1200 万像素。
- `--gap 0`：控制两个主体的横向间距，单位是整体适配画布前的像素；不指定时自动留少量空隙。
- `--scale-1 1.0 --scale-2 0.5`：分别设定相对原像素倍率，仅在用户明确要求时使用。
- `--rotate-1 90` / `--rotate-2 270`：分别逆时针旋转，支持 0、90、180、270 度；用户未要求就不旋转。
- `--background '#ffffff'`：设置预览底色，背景将带有一张连续的中性地面；无论选择何种预览底色，都会另存带接触阴影的透明底组合 PNG。
- `--enhance`：对两件商品做本地基础调光；默认保留输入观感。不会生成或补画包装细节。
- `--photo-profile-1` / `--photo-profile-2`：只使用分别与对应原照 SHA-256 和尺寸一致且人工核对过的轮廓配置，不得跨图复用。

脚本返回 `preview`、`transparent`、`source_1`、`source_2`、`subject_1`、`subject_2`、`review` 的绝对路径；保存两张原照的逐字节副本、各自原像素透明抠图、透明底拼图、背景预览和逐件复核 JSON。原照备份用 SHA-256 检查，防止临时附件清理后丢失溯源。每张原图单独记录哈希、原始抠图尺寸、位置、旋转、缩放、接触点与蒙版诊断；统一地面和阴影方向仅为视觉合成记录，不代表真实物理已验证。`visual-review-required` 只说明尺寸未被显著放大，**不表示原片小字清楚或抠图已合格**。

## 验收与下游

打开两张原照、各自透明抠图、最终拼图，逐件核对盒体和软管是否完整、白色盖子、包装字样、颜色、边缘及顺序，并确认两件商品在同一连续支撑平面上、各自有可信接触点和一致的阴影光向。自动蒙版可能漏件或带底色；有缺件、穿孔或明显白边时修复或要求清晰透明素材重跑，不能标记通过。拍摄模糊或曝光不足时，基础调光、插值都不能凭空恢复印字；若放大使原始细节不足、或人工检查发现细节模糊，则成品只能作为“仅看版式，勿上架”的预览。

向用户直接展示带地面背景的实际预览，并给出透明底拼图绝对路径，说明图号顺序、前后关系、背景和复核状态。透明底只有主体与接触阴影，不含地面；后续使用时必须配合透视一致的平面背景。拼图是扁平 PNG，不是可编辑 PSB。若用户要求“先拼图再做商品主图/详情”，先完成并检查拼图，再把其透明组合输入相应流程；跟踪两张原照各自的来源及每一步缩放，结合最终成图逐件复核地面、接触、光向和商品细节。**目前旧主图与详情图渲染器会在组合整体下方额外画一层阴影，实际可能产生双重阴影或悬浮；默认只作版式预览，不代表落地验收通过。**要交落地成品，须进一步处理额外阴影及背景并重新目视核对，无法消除时明确说明，不能当作合格成图。不能只看合成 PNG 的像素尺寸就声称包装清晰或可上架。
