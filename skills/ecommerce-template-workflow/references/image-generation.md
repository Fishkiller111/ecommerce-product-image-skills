# 图片生成：默认用 GPT 内置，APIMart 可选

## 选择工具

- **单独白底图或透明抠图**：优先用当前会话 GPT 内置图片编辑工具，按 [统一 GPT 抠图流程](gpt-cutout.md) 逐张处理和验收。两种结果同时需要时先生成透明图，核验后再用确定性合成铺纯白底。用户明确要求仅本地或不上传时，使用同级 [本地商品抠图与精修技能](../../ai-ecommerce-product-images/SKILL.md)。未安装该技能时，可用套版技能的本地白底脚本，并说明实际使用方式。工具不可用时不静默改用本地或第三方工具。
- **需要新场景、复杂背景或生成式修复时，未选用或未配置 APIMart 就用当前会话的 GPT 原生图片生成/编辑工具**（Codex 中为 `image_gen`）。不需要 APIMart、`OPENAI_API_KEY` 或额外安装生图 CLI。直接使用当前工具的实际接口，不把第三方代理或 OpenAI API 脚本当作内置能力。内置生成由 GPT 服务处理，不是纯本机运算；用户要求只在本地处理时不调用。
- 只有用户主动选择 APIMart（本次选择，或明确为本工作流设为首选），已配置可用的连接或个人凭据，并已授权本次素材范围和可能计费时，才使用 APIMart。安装了相关 Skill 或环境里存在 Key 不等于授权；未选用时不查找密钥、不读取 APIMart 工作流、不发 API 请求。选了 APIMart 但未配置时，说明情况并走 GPT 内置；若用户明确限定只用 APIMart，不擅自换工具。
- 白底/透明抠图的内置工具不可用或未完成时停止并说明；不得自动回退。其他独立的固定模板工作仍可按用户明确需求执行，不把本地预览说成 GPT 生成。不要把换成第三方付费服务或配置 API Key 作为默认继续条件。APIMart 已提交、超时但状态不明时，不重复提交或跨工具自动重跑。

## 生成背景或场景

1. **只生成独立空场景**，按新图调用，不附加商品照片、不让模型画商品、包装或排文案。若使用已授权的 APIMart，调用已配置工具的文生图功能，不走商品原图上传流程。用文字描述用户要的色调、材质、画幅、光向、支撑面和商品位置；例如“竖版暖米色棚拍背景，漫射光，连续哑光台面，中央和页首留白；不要商品、文字、Logo 或水印”。风格参考先提取配色与布局，不把参考图的商品或卖点写进提示词。
2. 按当前工具输出确认真实文件。Codex 内置图若保存在 `$CODEX_HOME/generated_images/`，把本次选中且可打开的结果另存到项目输出目录；不要拿旧生成记录当新图，不覆盖原图。只有会话预览而拿不到文件时，不假报已保存或已合成。
3. 目视检查背景没有额外商品、文字和不合理支撑面。详情图在[详情方案](product-detail.md)的相应页面填入 `background`，并传真实原图或已核对的透明抠图，由本地脚本放商品和文字。只要无字场景图时，用原始透明商品等比合成，不重绘包装。固定 PSB 主图若同时被要求，仍走原套版流程，不用生成图替换母版。若背景不可用，保留本地预览并注明实际交付。

## 生成式修复（用户明确要求时）

- 默认调用 GPT 原生图片编辑，只提供确实需要修复的原照或透明商品；按照当前工具支持的参考图方式传入，不把 PSB、整张详情图或无关图片交给模型。锁定外形、商品数量、颜色、商标和可见包装印字，不补写不可辨认的小字，要求透明输出时检查实际 alpha。单独白底与透明抠图统一走上方 GPT 内置流程；仅当用户明确要求本地处理时使用本地工具。
- 使用 APIMart 修复商品时，根据 [APIMart 文档](https://docs.apimart.ai/llms.txt) 核对当前图生图、鉴权和异步任务接口。用已配置的凭据提交获授权的原照，仅请求本次所需的编辑，保留商品数量、结构、文字和标识。先查询已提交任务的状态，再下载候选图核验。不要把凭据或临时访问链接写进提示词、日志或交付文件。
- 将输出与原照逐项核对。生成式结果不能冒充原片；有改字、缺件或包装细节不可核实时，不替换原像素主图，也不当作可上架成品。只有用户接受内部参考时才交“勿上架”样张；如要套 PSB，且透明素材符合入模尺寸要求，使用 `--prepared-cutout --keep-product-look --ai-restored-preview` 标识样张。普通套版不必等 AI 通过；要恢复真实细节优先补拍。
- 交付时说明实际使用了 GPT 内置、APIMart，还是纯本地，以及哪些部分仅供复核。
