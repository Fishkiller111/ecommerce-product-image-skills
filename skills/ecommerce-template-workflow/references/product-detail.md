# 商品详情图：真实商品 + 背景 + 文字

此分支不是固定 PSB 主图。每张详情图是一个产品介绍画面：使用真实商品，搭配适合商品的美化背景，排入标题、辅助说明和用户提供的卖点。可参考用户给的图片决定色调、层次、产品占比和信息位置，但参考图里的商品、品牌、包装、文案、功效、价格、认证都不是本次商品事实，不得照搬。不要让图片生成模型重画商品或生成文字；文字由本地排版。

## 输入和版式

- 使用本次真实商品照或用户确认的真实透明 PNG。原照中同时有商品盒和软管时可保留整体；不能把参考图中的商品截出来冒充本次原图。多张来源图只有在用户确实要求组合时才分别抠图、等比合成为透明素材；两图可先使用 [商品拼图流程](product-collage.md)，保留各原图、透明素材和合成说明，不凭空增加商品或声称示意组合具有准确实物比例。下列渲染器单次接收一张照片或合成透明素材，不会自动识别多张图之间的关系。
- 只使用用户提供、授权或可从真实包装核实的内容；没有明确文案时使用“商品展示”等中性标题或暂留空白。不得从风格截图自行提取功效、疗效、承诺、认证或价格，不能以模型猜测补全。用户提供的宣传语按原字排版，但仍须由用户核实真实性和平台要求；涉及医疗、抑菌等表述更需审慎，预览不代表可上架。
- 默认一张竖图 1080×1440；用户指定尺寸在渲染器支持范围内优先（宽 480–3000、高 480–4000 像素，宽高比 0.5–1.5）。超出范围需分图或另行处理，不声称脚本已生成超长图。多页时按用户要求拆成数张、保留顺序和统一风格；不要把多张图误称已拼成长图。默认 `hero` 为上方标题、中央商品、底部卖点，适合横向包装；`features` 为上方标题、左侧编号说明、右侧商品，适合竖向商品。不要为了相似度遮挡、拉伸商品或让字不可读。
- 根据商品、用户描述或参考图选择色调：`lavender` 紫、`sage` 绿、`ocean` 蓝、`sand` 米、`rose` 粉。它们是可用的本地基础背景，并不保证复刻参考图。可以提供用户授权的无商品、无文字背景，经 `--background` 使用；如需生成更复杂的背景，先确认服务可用和费用/外部处理授权，只生成独立背景，不上传或重画商品及文字；失败时仍可用本地背景。默认不依赖 AI、APIMart 或上传商品照片。

## 由 Agent 生成文案并运行

先确认同级 `psb-template-product-swap` 已安装，按它的依赖说明配置 Python；macOS 原图自动抠图使用系统 Vision，Windows 使用本地 CPU 蒙版，首次下载模型需要联网但不上传商品图。工作目录用本技能目录绝对路径 `WORKFLOW_DIR`；不要要求普通用户写 JSON 或提供 SKU。为本次任务创建 UTF-8 文案 JSON（例如 `outputs/detail-copy/<唯一编号>.json`），保留用户原字、数字与顺序：

```json
{
  "title": "商品外观展示",
  "subtitle": "包装与细节",
  "points": ["正面展示", "包装细节"],
  "palette": "sage",
  "layout": "hero"
}
```

字段：`title` 标题；`subtitle` 可为空；`points` 为 0–6 条短说明；`palette` / `layout` 按上文选择。需要超过 6 条时拆页；遇到排版报文字过长，不得静默截断或丢弃文字。没有文案时可不传 `--text-json`，仅以“商品展示”为中性标题。示例文字仅说明格式，不是必须套用的宣传语。

macOS（`PSB_PYTHON` 可指向已装依赖的解释器）：

```bash
DETAIL_PYTHON="${PSB_PYTHON:-python3}"
"$DETAIL_PYTHON" "$WORKFLOW_DIR/scripts/render_detail.py" "$SOURCE_IMAGE" \
  --text-json "$DETAIL_COPY" --out "$OUT_ROOT"
```

Windows PowerShell（按同级技能配置 `$env:PSB_PYTHON`，如包含中文或空格须引号）：

```powershell
& $env:PSB_PYTHON (Join-Path $WorkflowDir 'scripts\render_detail.py') $SourceImage `
  --text-json $DetailCopy --out $OutRoot
```

`OUT_ROOT` 默认项目的 `outputs/product-detail`，脚本自动生成不重复编号及子目录，已有结果绝不覆盖。可按需加 `--sku` 指定唯一编号、`--size 750x1000`、`--background 背景.png`、`--enhance`（本地商品调光；默认保留输入观感）、`--photo-profile 配置.json`（只对 SHA-256 和尺寸都匹配的原照有效）。只有已配置并通过同照片核对的轮廓才可使用，不要把白底图直接视为透明图，也不能把白色包装抠掉。

脚本返回 `preview`、`cutout`、`background`、`copy`、`review` 的绝对路径，另保存输入指纹、画布、文案、排版、置入尺寸、蒙版诊断和上架状态。它仅调用同级技能的抠图、字体、尺寸检查和可选基础调光，不打开或套用 PSB 母版，不产生可编辑 PSB。

## 验收与交付

打开最终详情图和原像素透明商品，与实际原图逐项比较：商品数量、盒／管／盖、轮廓、颜色、比例、包装文字、阴影、图文遮挡、文字完整性。自动蒙版和像素尺寸检查均不等于通过人工复核；原本就是模糊照片时，即使尺寸达标也仍可能无法辨认包装细字。确认缺件、白边、包装抠空或文案错误先修正再交；不能成功出图就报告实际失败步骤，保留可用中间文件。

- 能看但未上架复核：展示**实际生成的详情 PNG**和绝对路径，说明需核对商品、文案和平台规则；成品是扁平 PNG。
- `native-detail-insufficient` 或成图细字不清：若主体完整，仍可展示为“仅看版式，勿上架”，建议补拍清晰近照；不得把插值说成修复了原字。若商品不完整，不当作合格预览交付。
- 详情图可以与主图同时交付，但各自保留输出、文案和复核记录，不能将任一路径的 PNG 冒充另一路结果。
