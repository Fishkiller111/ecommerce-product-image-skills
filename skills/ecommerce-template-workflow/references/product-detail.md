# 商品详情图

将真实商品、经过核实的资料和独立背景排成本地详情图。用户说「做详情图／详情页」且未限定一张时，按现有素材制作一组手机端竖图。指定「只做成分图」「只要参数图」时只制作相应一屏。风格截图用来观察版式、衬底和视线顺序，本次原照、包装和用户资料用来确定商品与文字。

## 确定风格和屏序

这组参考图的基准宽度为 790 px。默认同宽分屏，画幅随每屏内容调整。首屏、成分、用法安排在前，参数、实拍与资质安排在后。按商品和素材增减、调序；照片多时可连续安排多个实拍屏。

先从包装取一种主色，配合空景的材质与光线统一整组视觉。场景首屏可用暖木窗影、远山或浅景深环境，成分屏用较深的空景衬托实拍与材料，参数和实拍用清晰浅底。边框按版式需要使用。标题以简明中文为主，正文、数字与单位先保证手机预览可读。

## 场景首屏与商品保真

1. 先定摆位。确定哪件是主商品、另一件如何靠近或倚靠、各自脚点、标题留白和来光方向。盒与管分拍时用两张真实透明层分别定位。主商品在手机宽度下仍应足够大，露出主印字，错落以高低、前后和轻微角度体现。站立或倾斜都要有可解释的接触关系。
2. 按摆位生成独立空背景。场景首屏默认按[独立背景生成](image-generation.md#生成背景或场景)用 GPT 内置生成空景，或直接使用用户给的真实空景。提示词写入台面高度、支撑平面、镜头、来光、留白、远景和道具位置。商品照片、文字和 Canny 导图留在本机。背景只包含环境，出现假包装、支撑面过窄或光向与实拍冲突时，修复或重生成背景。资源不足时将渐变底结果标为版式草图。
3. 本地合成。独立背景首屏采用满幅照片；原图商品仅做等比缩放、平移和必要的小角度旋转，阴影另画在下层，文字本地排。落脚以商品蒙版底端为准，检查贴台、遮挡、商品比例和包装文字。重新选择背景时保留已核对的透明层。
4. 运行 Canny 和像素比对。脚本用同摆位下的原照片图层和其下背景建立合成基准，再检查成图可见商品区域的 RGB 和边缘，输出 `Canny_XX.png`（轮廓与包装印刷边）和 `详情复核.json`。任一发生变化时先处理遮挡、误叠或边缘，并重新核验。对故意叠放，只核可见部分；包装的可读性与落脚阴影仍要目视确认。

| 屏 | 构图 | 素材与核对 |
| --- | --- | --- |
| 首屏 `hero` | 上方商品名，中央大实拍，下面可有一到两项已确认的短卖点。盒与管齐备时可用真实透明组合占据主视觉，保持包装比例和原印字。 | 本次原照或已核对的透明图。有明确场景风格时选用独立背景，注意光向、台面和接触阴影。 |
| 成分 `ingredients` | 商品居中，成分卡分列两侧。同一组统一形状、取景与字号，通常 2–4 项。用一张材料近照和一个准确名称讲清一项。 | 成分名以本商品配料表或说明书为准，使用核对过的对应材料图和部位。没有可靠材料图时用文字卡。示意图应按需标注「成分示意」，不当作实拍，不从原料推导浓度、配比、功效或适用范围。 |
| 使用 `usage` | 放大实际操作、质地或手持图，按顺序放简短说明。只有用法文案时，可用商品实拍配步骤卡。 | 真实使用图和该商品的已确认使用说明。没有图可用文字和现有商品图；无法确认动作、用量或频次时跳过相关内容。 |
| 参数 `specs` | 米白参数卡，标签和值分列，细线分行。根据字段拆屏，规格数字和单位完整显示。 | 从本次包装、说明书或已核实的资料录入实际字段。只显示已知项，长用法或注意事项无损拆屏。 |
| 实拍 `gallery` | 浅底大图。横向盒照逐行排列，竖向盒或软管可并列对照。一屏 1–3 张，标签按需要加。 | 各角度分别提供实际照片。保持真实角度和比例，需要看包装小字时单列一屏或使用清晰近拍。 |
| 资质／检测 `documents` | 资料原件等比置入浅色卡框，有需要可分屏突出单份文件。检测依据可独立于用法放同组，标题直接标示实际报告主题。 | 仅使用用户提供且确认可公开、与当前商品或主体对应的真实文件页。核对机构、适用对象、报告日期和有效期。缺少材料时略过该屏。检测或资质图自始至终使用原件，保留页内文字，不用风格截图的证书、宣称或印章。 |

包装独立成层。可使用本地抠图或已经验边、调色的透明 PNG。基础版式可用[商品拼图流程](product-collage.md)中的透明组合，场景首屏优先分别摆放。白色包装、盖子、管口、品牌、文字、条码和规格在原图与成品间逐一比对。

## 交付用脚本

Agent 在用户输出目录内写 UTF-8 方案，按需要填入各屏。用户只需给原照、实际资料和目标风格。相对路径以方案文件所在目录为准。下面只示范两屏的字段结构，实际填写本次商品的信息。

```json
{
  "product": "assets/product.png",
  "palette": "heritage",
  "width": 790,
  "pages": [
    {"kind": "hero", "title": "商品展示"},
    {"kind": "gallery", "title": "产品实拍", "items": [
      {"label": "正面", "image": "assets/front.jpg"},
      {"label": "侧面", "image": "assets/side.jpg"}
    ]}
  ]
}
```

- 一组为 1–12 屏。每屏支持 `kind`、`title`、`subtitle`、`items`。条目用 `label`、`text`、`image` 和可选 `source`。用 `source` 在复核 JSON 记下资料出处，例如实拍包装侧面或说明书页码。这个字段只进入复核记录。
- `hero` 的文字卡最多 2 项，可省略。成分卡最多 6 项，每项 `label` 填成分名，`image` 和 `text` 按实际素材选填。`usage` 最多 4 项，可有一项使用实拍。参数卡最多 7 行，每行提供标签与值。实拍与资质每项必须给图，实拍标签可省略。资质每屏最多 4 份。`hero` 和 `ingredients` 需要 `product`，纯参数、实拍或资质等任务可直接使用各自资料。
- 默认为 `heritage`（米白、暖金、松绿），也可选 `sage`、`sand`、`ocean`、`rose`、`lavender`。宽度支持 600–1600。首屏、成分、资质与没有使用实拍的商品用法屏可指定 `background`，使用独立无字场景。参数与实拍用清晰浅底。
- 场景首屏的 `background` 指向独立空景，`product_layers` 可分别安排 1–3 张透明商品图。每项有 `image`、`anchor`（相对画布的商品横向中心、接触台面的底端）、`height`（商品高度占画布的比例）、`angle`（可选，逆时针为正）。按从后到前的顺序写。例如一项可写为 `{"image":"assets/carton.png","anchor":[0.43,0.84],"height":0.55,"angle":0}`。指定这些图层时该首屏可省略顶层 `product`。
- 默认输出每屏一张 PNG 和 `详情复核.json`，用户需要长图时加 `--long`，同时保留逐屏图。若一屏文案塞不下，拆屏或重新排版，保留原字、数字和顺序。

脚本复用同级 `psb-template-product-swap` 的本机抠图和字体，商品边缘检查使用 `opencv-python-headless`。使用装好这两组依赖的 Python 3.12，或用 `PSB_PYTHON` 指定已有解释器。指定 `WORKFLOW_DIR` 及方案路径后运行：

```bash
DETAIL_PYTHON="${PSB_PYTHON:-python3.12}"
"$DETAIL_PYTHON" "$WORKFLOW_DIR/scripts/render_detail_series.py" "$DETAIL_PLAN" \
  --out outputs/product-detail
```

macOS 已装 `uv`、解释器尚缺依赖时，可用 `uv run --python 3.12 --with-requirements "$WORKFLOW_DIR/../psb-template-product-swap/requirements.txt" --with 'opencv-python-headless>=4.8,<5' python` 运行同一脚本。在 Windows 的现有环境中安装同一 OpenCV 包。

```powershell
& $env:PSB_PYTHON (Join-Path $WorkflowDir 'scripts\render_detail_series.py') $DetailPlan `
  --out outputs/product-detail
```

原先的 `render_detail.py <原图> --text-json <文案>` 仍用于明确要求沿用 `hero` 或 `features` 的基础单图版式。增强详情图走本页方案脚本。

## 验收

按顺序打开实际 PNG，先看手机宽度下主标题、正文、参数和成分名，再看原尺寸核对主体、盒盖、印字、条码、成分名、用法、资料出处和图文遮挡。检查背景接触关系和组图边距。拼接长图时逐屏比对顺序和接缝。素材不足而省略的屏在交付里说明。文字无法核对的图可作为版式样张，清晰度检查与预览状态写进复核记录。交付分屏图的路径，用户要求拼接时随附长图路径。
